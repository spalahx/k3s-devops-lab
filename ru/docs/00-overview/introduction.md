# Введение

Одна машина с Ubuntu Server (домашний мини-ПК или облачный VPS) запускает K3s — облегчённый Kubernetes. Каждый проект описывается YAML-манифестами, а управление идёт по SSH с ноутбука. Если вам хватает одного `docker compose` на ноутбуке, эту схему можно пропустить.

## Что получается

- Один постоянно включённый Linux-хост с защищённым входом по SSH (только ключи, firewall, защита от перебора).
- Docker для сборки образов и K3s для их запуска; Traefik направляет HTTP-трафик в проекты по имени хоста.
- Код на сервере редактируется из IDE на ноутбуке через Remote-SSH; изменения видны в запущенных Pod через `hostPath`.
- Опционально: удалённый доступ через VPS, CI/CD, мониторинг (Prometheus, Grafana, Loki), файловое хранилище.

## Когда это полезно

- **Слабый или загруженный ноутбук.** Базы данных, несколько веб-стеков и браузер вместе не помещаются; рантайм уезжает на сервер, локально остаётся только IDE.
- **Общий dev-сервер для небольшой команды.** Один хост, один namespace на проект, каждый подключается по SSH со своим ключом.
- **Параллельная работа над несколькими проектами и интеграционное тестирование.** Проекты работают рядом на разных именах хостов без конфликтов портов и зависимостей.
- **Окружение, близкое к production.** Те же объекты Kubernetes (Deployment, Service, Ingress), что и в production, используются уже при разработке.
- **Эксперименты.** Временные namespace и новые инструменты с ограничениями ресурсов, чтобы не отнимать их у остальных проектов.
