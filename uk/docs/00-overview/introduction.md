# Вступ

Одна машина з Ubuntu Server (домашній міні-ПК або хмарний VPS) запускає K3s, легкий Kubernetes. Кожен проєкт описується YAML-маніфестами, а керування машиною відбувається через SSH з ноутбука. Пропустіть це налаштування, якщо вам вже вистачає одного файлу `docker compose` на ноутбуці.

## Що ви отримуєте

- Один Linux-хост, що працює безперервно, із захищеною точкою входу SSH (вхід лише за ключем, брандмауер, захист від перебору паролів).
- Docker для збирання образів і K3s для їх запуску; Traefik маршрутизує HTTP-трафік до проєктів за іменем хоста.
- Код на сервері редагується з IDE на ноутбуці через Remote-SSH; зміни з'являються в запущених Pod через томи `hostPath`.
- Опційно: віддалений доступ через VPS, CI/CD, моніторинг (Prometheus, Grafana, Loki), файлове сховище.

## Коли це корисно

- **Слабкий або завантажений ноутбук.** Бази даних, кілька веб-стеків і браузер разом не вміщуються; перенесіть середовище виконання на сервер, а локально залиште лише IDE.
- **Спільний dev-сервер для невеликої команди.** Один хост, один namespace на проєкт, усі підключаються через SSH зі своїм ключем.
- **Паралельна робота над кількома проєктами та інтеграційне тестування.** Кілька проєктів працюють одночасно на різних іменах хостів без конфліктів портів і залежностей.
- **Середовище, подібне до продакшену.** Під час розробки використовуються ті самі об'єкти Kubernetes (Deployment, Service, Ingress), що й у продакшені.
- **Експерименти.** Тимчасові namespace та нові інструменти з обмеженнями ресурсів, щоб вони не позбавляли ресурсів інші проєкти.
