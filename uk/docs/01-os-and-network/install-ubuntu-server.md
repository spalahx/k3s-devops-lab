# Встановлення Ubuntu Server

Встановлює Ubuntu Server LTS на «голу» машину з USB-флешки. Пропустіть, якщо машина є хмарним VPS, на якому вже є Ubuntu (див. [Відмінності локального та хмарного середовища](../00-overview/local-vs-cloud-differences.md)).

## 1. Вибір образу

| Вибір | Значення |
|---|---|
| Дистрибутив | Ubuntu Server (без графічного середовища), остання LTS (наприклад, 26.04 LTS; LTS = 5 років оновлень безпеки) |
| Архітектура | `amd64` для машин Intel/AMD, `arm64` для ARM-плат. Неправильна архітектура не завантажується |
| Завантаження | `https://ubuntu.com/download/server` (ISO близько 2 ГБ) |

Перевірте завантажений файл за опублікованою сумою SHA256:

```bash
# macOS
shasum -a 256 ~/Downloads/ubuntu-*-live-server-amd64.iso
# Linux
sha256sum ~/Downloads/ubuntu-*-live-server-amd64.iso
```

## 2. Запис USB-флешки

Використовуйте флешку від 8 ГБ. Усе на ній буде стерто.

### macOS

```bash
diskutil list                         # знайдіть флешку за розміром, напр. /dev/disk4 (external, physical)
diskutil unmountDisk /dev/diskN
sudo dd if=~/Downloads/ubuntu-XX.XX-live-server-amd64.iso of=/dev/rdiskN bs=1m status=progress
diskutil eject /dev/diskN
```

### Linux

```bash
lsblk                                 # знайдіть флешку, напр. /dev/sdb (не розділ на кшталт sdb1)
sudo umount /dev/sdb* 2>/dev/null
sudo dd if=~/Downloads/ubuntu-XX.XX-live-server-amd64.iso of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

- `rdiskN` на macOS є raw-пристроєм і пише набагато швидше, ніж `diskN`.
- `dd` не просить підтвердження. Неправильна ціль `of=` (наприклад, внутрішній диск `disk0`) знищить цей диск. Двічі перевірте розмір у `diskutil list` / `lsblk`.
- `Resource busy` на macOS означає, що флешка досі змонтована: виконайте `diskutil unmountDisk` ще раз.

## 3. Завантаження машини з USB

1. Підключіть машину до роутера Ethernet-кабелем. Використовуйте дротову мережу для встановлення: інсталятор завантажує пакети, а для деяких Wi-Fi-чипів в інсталяторі немає драйвера (див. [Усунення проблем із мережею](../99-appendix/troubleshooting-networking.md)).
2. Підключіть монітор і клавіатуру (потрібні лише доки не запрацює SSH).
3. Вставте флешку, увімкніть живлення і багаторазово натискайте клавішу меню завантаження (зазвичай `F7`, `F10`, `F11`, `F12`, `Esc` або `Del`; залежить від виробника).
4. Виберіть пункт, що починається з `UEFI:` і містить назву флешки. Не вибирайте `Legacy`.

Якщо флешки немає в списку: скористайтеся іншим USB-портом (бажано USB 2.0), перезапишіть флешку іншим інструментом і переконайтеся, що Secure Boot її не блокує (ISO Ubuntu підписаний і зазвичай завантажується з увімкненим Secure Boot).

## 4. Вибір в інсталяторі

Інсталятор текстовий: стрілки, `Tab`, `Space` (перемикання), `Enter`.

| Екран | Вибір |
|---|---|
| Мова / клавіатура | English (повідомлення про помилки легше шукати) |
| Тип встановлення | `Ubuntu Server` (не minimized) |
| Мережа | Дротовий інтерфейс має показувати адресу через DHCP. Залиште як є; статичну IP-адресу задають пізніше ([Статична IP-адреса](static-ip-and-networking.md)) |
| Проксі / дзеркало | За замовчуванням |
| Сховище | Використати весь диск, залишити ввімкненим «Set up this disk as an LVM group» (розділи можна буде змінити пізніше). Виберіть внутрішній диск, а не USB-флешку |
| Профіль | Ваше ім'я, ім'я сервера `<SERVER_HOSTNAME>`, ім'я користувача `<SERVER_USER>`, надійний пароль (він усе ще потрібен для `sudo` після вимкнення входу в SSH за паролем) |
| Ubuntu Pro | Пропустити |
| SSH | **Позначте «Install OpenSSH server»**. Не імпортуйте ключі зараз |
| Featured snaps | Нічого не вибирайте |

Дочекайтеся завершення встановлення й оновлень (10-20 хвилин), потім виберіть **Reboot**. Коли з'явиться запит, **витягніть USB-флешку** перед натисканням `Enter`, інакше машина знову завантажить інсталятор.

> **Попередження:** якщо OpenSSH server не було позначено, встановіть його на консолі: `sudo apt install openssh-server`.

## 5. Перший вхід і оновлення

На консолі увійдіть як `<SERVER_USER>` (пароль під час введення не відображається). Дізнайтеся адресу:

```bash
ip -br a
```

Приклад: `enp1s0  UP  192.168.1.150/24`. Назви інтерфейсів (`enp1s0`, `eno1`, `eth0`) відрізняються залежно від машини.

Далі працюйте з ноутбука; монітор і клавіатура більше не потрібні:

```bash
ssh <SERVER_USER>@<SERVER_IP>
```

Відповідайте `yes` на запит про відбиток хоста під час першого підключення (він зберігається в `~/.ssh/known_hosts` і попередить, якщо хост пізніше зміниться). Потім оновіть систему:

```bash
sudo apt update && sudo apt upgrade -y
sudo reboot        # якщо було оновлено ядро або libc
```

## Перевірка

```bash
lsb_release -d                       # Ubuntu LTS
systemctl is-active ssh              # active
ip -br a                             # дротовий інтерфейс має адресу
sudo apt update && apt list --upgradable   # нічого (або лише утримувані пакети) не лишилося
```

## Типові збої

| Симптом | Причина / виправлення |
|---|---|
| Інсталятор не бачить мережі | Перепідключіть кабель, спробуйте інший кабель/порт, перевірте, що роутер роздає DHCP |
| `ssh: Connection timed out` | Неправильна IP-адреса або ноутбук в іншій мережі; перевірте ще раз `ip -br a` на сервері |
| `ssh: Connection refused` | OpenSSH server не встановлено або не запущено: `sudo apt install openssh-server && systemctl status ssh` |
| Втрачено пароль користувача | Потрібен доступ до консолі та режим відновлення GRUB, або перевстановлення |
